HEART DISEASE PREDICTION PROJECT — FULL ML SUMMARY

1. Problem Definition

This project aims to predict the probability of heart disease using a
large real-world healthcare dataset. The dataset is highly imbalanced,
meaning there are far more healthy patients than diseased patients. In
medical machine learning, missing a sick patient is dangerous, so recall
and ROC‑AUC are prioritized over raw accuracy. This reflects correct
healthcare ML thinking.

2. Dataset Understanding

The dataset contains approximately 320,000 records with 18 columns such
as: - BMI - Smoking status - Diabetes - Physical and mental health - Age
category - Lifestyle indicators

Most columns are categorical text. To prepare the data for machine
learning: - One‑hot encoding (pd.get_dummies) was applied - Feature
count expanded from 17 raw features to 37 encoded features

This represents real-world tabular ML preprocessing.

3. Machine Learning Pipeline

A full supervised ML pipeline was implemented:

1.  Load dataset
2.  Inspect and clean data
3.  Encode categorical variables
4.  Train–test split
5.  Feature scaling
6.  Handle class imbalance
7.  Train multiple ML models
8.  Evaluate using medical metrics
9.  Tune decision threshold
10. Save deployable artifacts

This is an industry-style ML workflow.

4. Models Compared

The following models were trained and evaluated:

-   Logistic Regression
-   Decision Tree
-   Random Forest
-   XGBoost

Model comparison demonstrates proper experimental methodology rather
than a single tutorial model.

5. Evaluation Metrics

Instead of focusing only on accuracy, the project used:

-   Precision
-   Recall (critical in healthcare)
-   F1 Score
-   ROC‑AUC (probability quality)

Key insight: High accuracy can be misleading in imbalanced medical
datasets.

6. Best Model Selection

Logistic Regression achieved the best performance:

-   Highest ROC‑AUC (~0.84)
-   Highest Recall (~0.78 before tuning)

Important interpretation: A simple linear model can outperform complex
models when the dataset is mostly linearly separable. This reflects
mature ML reasoning.

7. Decision Threshold Tuning

Rather than using the default 0.5 probability threshold:

-   Multiple thresholds were scanned
-   Optimal threshold selected: 0.68
-   Achieved better balance of Precision and Recall
-   Improved F1 score and clinical usefulness

This is an advanced and realistic healthcare ML practice rarely seen in
beginner projects.

8. Deployment‑Ready Artifacts

The following files were exported:

-   final_heart_model.pkl → trained model
-   scaler.pkl → preprocessing scaler
-   decision_threshold.pkl → tuned probability threshold
-   feature_columns.pkl → encoded feature column order

These enable a production‑ready inference pipeline.

9. End‑to‑End Inference System

A Flask backend API was created that:

1.  Accepts raw patient inputs
2.  Applies the same preprocessing used during training
3.  Restores encoded feature structure
4.  Scales the features
5.  Predicts probability of heart disease
6.  Applies the tuned clinical threshold
7.  Returns JSON prediction output

Example prediction: - Probability ≈ 15.9% - Threshold = 0.68 - Final
prediction = No heart disease

This confirms a fully working ML deployment pipeline.

-   Medical metric prioritization

-   Real backend inference API
